# Exit plan for holdings — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each holding shows an exit plan (a price range on the re-check date, a sell-at price with its chance, a break-even line when under water, the chance the stop comes first) in place of the bare "Exit by" date, with every chance checked against history before it is shown as validated.

**Architecture:** A new pure module `advisor/portfolio/exit_plan.py` simulates 4,000 block-bootstrap price paths per holding and reads the plan off them. The holdings stage stores the plan as `holding_actions.exit_plan` (jsonb). A benchmark check measures calibration per class and stores a verdict in the benchmark report; the stage reads the latest verdict and hides what failed. The grader records what really happened. The web shows the plan on My Portfolio and the ticker page and offers a prefilled price alert.

**Tech Stack:** Python 3.12, numpy, pandas, psycopg, pytest (in Docker: `bash pipeline/scripts/in-docker.sh uv run pytest …`); Next.js 16 / React 19, Vitest, Supabase.

**Spec:** `docs/superpowers/specs/2026-11-20-exit-plan-design.md`. It is the authority; read it with this plan. Where the controller's rulings (last section) depart from it, the rulings win; each departure is written into the task it affects.

## Global Constraints

- `decide()` and the Sell / Trim / Add / Hold rules are untouched. The `exit_by` column keeps today's values and meaning.
- Constants, in `exit_plan.py`: `PLAN_VERSION = 1`, `PATHS = 4000`, `BLOCK = 5`, `LOOKBACK = 252`, `MIN_CLOSES = 60`, `TOUCH = 1 / 3`, `NO_FORECAST_HORIZON = 21`.
- Point-in-time: a plan built for day D reads only closes dated on or before D. The benchmark check reads nothing after the sample day to build a plan, and only later closes to judge it.
- Deterministic: the seed comes from the symbol and the feature day; the same inputs give the same plan on any machine (no Python `hash()`).
- All path arithmetic is in log space; a quantile `q` becomes `log(1 + q)`.
- A plan that cannot be built is null with a reason in the run summary; it never fails the stage. No NaN reaches the stored plan (Postgres jsonb rejects it, and the one transaction would lose every action): "no price" covers None, NaN and ≤ 0, and a plan with any non-finite number is refused.
- **Re-check date (R5):** `exit_plan.recheck_by` = the feature day + the plan's own horizon on the asset's calendar (sessions for a stock, calendar days for a coin), always. A pick-linked holding's later exit-by stays in the `exit_by` column only, and the grader counts touches up to `recheck_by`. This deviates from the last sentence of spec §1 (the controller's call): the chances are simulated over the plan's horizon, so a later date would overstate them.
- **Coins (R3):** every coin plan is volatility-only, live and in the check, even for a coin with model rows. Spec §2's coin-with-forecast path is deferred (recorded in Task 9).
- **Live/check parity (R6):** live and the benchmark check build a plan the same way, through `build_plan`: cost = `round_trip_cost` for the asset; drift = the benchmark's median over the windows inside its last `LOOKBACK` closes up to the day; moves from the last `LOOKBACK` closes (at most 251 returns). The check samples usable horizons only.
- **Closes only (R9):** touches are counted on daily closes in the simulation, the check and the grader. Intraday touches are not measured (`DailyPanel` holds closes only), so a limit order's real fill chance is a little higher than shown. The page says "closes at or above".
- **Skew (F11):** the simulation matches the forecast's median and its 10–90 width, not its skew. For a skewed forecast, q10 and q90 can each be off by about 0.005 in log terms.
- Wording (spec §8): never "target price" or "will reach". Use "range", "sell at", "about 1 in 3", "reached in N% of cases". Every plan names its basis: "from the model's forecast" or "from volatility only — no view on direction".
- Prices are in the asset's own currency: USD for US stocks and coins, CAD for TSX stocks.
- Acceptance tolerances (spec §6), in `benchmark/exit_check.py`: touch rate within ±5 points of 1/3 overall and ±8 in each volatility third; range coverage within ±5 points of 80%; break-even and stop-first chances in five bins, worst bin within ±10 points. Rates are stored as fractions, tolerances in points. Result (R7): `fail` when the range check fails; `range_only` when the touch or value check fails; else `pass`; a failed break-even or stop-first check hides only its own chance. Value rule (R10): over pairs with a sell-at price, mean(with_order − without_order) ≥ 0 pooled and in at least ⌈folds / 2⌉ of the calibrated folds that have such pairs (2 of 3).
- Docker has a 4 GB cap, and a full-US walk-forward runs out of memory locally: the benchmark check samples pairs and is never run on real data on this machine.
- `web/`: read the relevant guide in `web/node_modules/next/dist/docs/` before writing page code (`web/AGENTS.md`).
- `git commit` runs as its own shell command (a hook blocks any `-n` flag in the same command). Never `--no-verify`. No push, no merge. Commit trailer as the session's attribution reminder gives it.

## Review Focus

1. A holding with fewer than 60 closes, a zero, missing or NaN price, or a forecast whose simulated excess has no spread (10–90 width of 0): the plan is null with a reason, no NaN reaches the jsonb, and the other holdings still get theirs. (Tasks 1, 2, 3)
2. A forecast with `q10 <= -1`, or quantiles out of order (anything but `−1 < q10 ≤ q50 ≤ q90` with `q10 < q90`, all finite): no `log` of a non-positive number; the plan is null with a reason. (Task 1)
3. A holding at or above its cost: `breakeven` and `p_breakeven` are null. A holding whose `sell_at` is at or under the stop, or at or under price × (1 + round-trip cost): `sell_at` and `p_touch` and `p_stop_first` are null, the range stays. (Task 2)
4. A stored action row from before this change (`exit_plan` null): the page renders the old date and nothing else. A plan with a failed class verdict: the page renders the status note and the re-check date only. Neither crashes or shows "undefined". (Tasks 7, 8)
5. A benchmark check sample day near the end of history, where the horizon's closes do not all exist yet: the pair is left out, not judged on a short window. (Task 5)
6. A holding linked to an open pick with a later exit-by: `exit_plan.recheck_by` is the feature day + the plan's own horizon, `exit_by` keeps the pick's date, and the grader counts touches up to `recheck_by` (R5). A holding whose stop exits early is graded only once its re-check date has a final close, so its touches read the whole window (R4). (Tasks 2, 3, 4)
7. A held coin with model rows (BTC is benchmarked to SPY, which is in `view.bars`): its plan is volatility-only and `view.bars` is never read for it (R3). (Task 3)
8. A forecast plan after the active model config changes: "Not validated yet" until a benchmark judges the new config, because the verdict is keyed by the config's name (R2). (Tasks 5, 6)
9. The page says the chances count closes ("closes at or above"); nothing claims an intraday fill chance (R9). (Task 8)

### Task 1: the simulated paths

**Files:**
- Create: `pipeline/src/advisor/portfolio/exit_plan.py`
- Test: `pipeline/tests/unit/test_exit_plan_paths.py`

**Interfaces — Produces:**
- The constants above.
- `class NoPlan(ValueError)`: its message is the reason shown in the run summary. Messages used: `"too little price history"`, `"no price"`, `"forecast range has no width"`, `"forecast is not usable"`, and (raised by `build_plan`, Task 2) `"plan is not finite"`.
- `seed_of(symbol: str, day: date) -> int` — the first 8 bytes of `sha256(f"{symbol}|{day.isoformat()}")` as an unsigned int.
- `median_drift(bench_closes: Sequence[float], horizon: int) -> float` — the median simple return over every overlapping `horizon`-step window of the benchmark's closes; raises `NoPlan("too little price history")` when there is no full window.
- `paired_moves(closes: Mapping[date, float], bench: Mapping[date, float]) -> np.ndarray` — shape (n, 2): the asset's and the benchmark's daily log returns between consecutive closes the two have in common (dates only one side has are dropped), over the last `LOOKBACK` common closes, oldest first: at most `LOOKBACK − 1` = 251 rows.
- `simulate_raw(moves: np.ndarray, horizon: int, seed: int) -> np.ndarray` — the block sampler alone (no demeaning, no rescaling): the cumulative sum of the sampled rows of a 1-D `moves`, shape `(PATHS, horizon)`. `simulate` is built on it and uses the same block indexes for both columns of a pair.
- `simulate(moves: np.ndarray, horizon: int, seed: int, *, forecast: tuple[float, float, float] | None = None, drift: float | None = None) -> np.ndarray` — shape `(PATHS, horizon)`: each path's cumulative log return after each step.
  - `moves` is shape (n,) for an asset with no forecast, or (n, 2) from `paired_moves` with a forecast. Fewer than `MIN_CLOSES - 1` rows raises `NoPlan("too little price history")`.
  - Block bootstrap: each path is `ceil(horizon / BLOCK)` blocks of `BLOCK` consecutive rows, block starts drawn uniformly from `0 … n − BLOCK` with `np.random.default_rng(seed)`, truncated to `horizon` steps.
  - Without a forecast: the sample mean of `moves` is removed before sampling.
  - With a forecast `(q10, q50, q90)` and `drift`: the excess column is `moves[:, 0] − moves[:, 1]`. One scale multiplies every sampled excess step so the 10–90 width of the summed ends equals `log(1 + q90) − log(1 + q10)`; then a constant per-step shift makes the median end equal `log(1 + q50)`. The benchmark column has its sample mean removed and a constant per-step shift so its median end equals `log(1 + drift)`. A path is the cumulative sum of the two. Skew between q10, q50 and q90 is not reproduced (Global Constraints).
  - Refused with `NoPlan("forecast is not usable")` unless all three quantiles are finite and `−1 < q10 ≤ q50 ≤ q90` with `q10 < q90`; a simulated width of 0 raises `NoPlan("forecast range has no width")`.

def test_with_a_forecast_the_ends_match_the_quantiles_and_the_benchmark_drift():
    rng = np.random.default_rng(3)
    bench = rng.normal(0.0004, 0.01, 252)
    pair = np.column_stack([bench + rng.normal(0, 0.02, 252), bench])
    paths = simulate(pair, 21, 7, forecast=(-0.08, 0.02, 0.15), drift=0.01)
    ends = paths[:, -1]
    # excess quantiles composed with the benchmark's median drift: 0.0198 + 0.0100 = 0.0298
    assert np.median(ends) == pytest.approx(math.log(1.02) + math.log(1.01), abs=0.01)
    assert np.quantile(ends, 0.9) - np.quantile(ends, 0.1) > math.log(1.15) - math.log(0.92)  # benchmark spread adds

    rng = np.random.default_rng(3)
    bench = np.full(251, 0.0004)  # no benchmark spread: the ends are the excess plus the drift
    pair = np.column_stack([bench + rng.normal(0, 0.02, 251), bench])
    ends = simulate(pair, 21, 7, forecast=(-0.08, 0.02, 0.15), drift=0.01)[:, -1]
    assert np.median(ends) == pytest.approx(math.log(1.02) + math.log(1.01), abs=0.005)  # 0.02975
    width = np.quantile(ends, 0.9) - np.quantile(ends, 0.1)

### Task 2: reading the plan off the paths

**Files:**
- Modify: `pipeline/src/advisor/portfolio/exit_plan.py`
- Test: `pipeline/tests/unit/test_exit_plan_read.py`

**Interfaces:**
- Consumes: `simulate`, `paired_moves`, `median_drift`, `NoPlan` (Task 1).
- Produces:
  - `touch_share(paths: np.ndarray, level: float) -> float` — the share of paths whose maximum cumulative value is at or above `level` (log space).
  - `read_plan(paths: np.ndarray, price: float, *, stop: float | None, breakeven: float | None, cost: float) -> dict` — keys `low, mid, high, sell_at, p_touch, p_stop_first, p_up, breakeven, p_breakeven` (floats or None):
    - `low, mid, high` = `price × exp(q)` for the 10th, 50th, 90th percentile of the end values.
    - `sell_at` = `price × exp(level)` where `level` is the k-th highest path maximum, `k = ⌈TOUCH · N⌉` for N paths (`np.sort(maxima)[-k]`, with `k = math.ceil(round(TOUCH * N, 9))` so float error never adds one). `p_touch = touch_share(paths, level)`, compared in log space against that same value: k/N up to ties. (Not numpy's default quantile: on the six-path test below it gives 113.24, not 120.0.)
    - `sell_at`, `p_touch` and `p_stop_first` are None when `sell_at <= price × (1 + cost)` or (with a stop) `sell_at <= stop`.
    - `p_stop_first` = the share of paths whose first close at or under `stop` comes before their first close at or above `sell_at` (a path that never touches `sell_at` but does touch the stop counts); None without a stop.
    - `p_up` = the share of paths ending above 0.
    - `breakeven`, `p_breakeven`: the price passed in and `touch_share(paths, log(breakeven / price))`; both None when `breakeven` is None.
  - `build_plan(*, symbol: str, day: date, closes: Mapping[date, float], price: float | None, horizon: int | None, forecast: tuple[float, float, float] | None, bench_closes: Mapping[date, float] | None, stop: float | None, cost_cad: float, value_cad: float, cost: float, recheck: Callable[[int], date] | None = None) -> dict` — the stored plan: `read_plan`'s keys plus `version = PLAN_VERSION`, `basis` (`"forecast"` or `"volatility"`), `drift` (None for volatility), `horizon`, `cost_price`, `recheck_by` (ISO string or None), `status = None`. These exact key names are what Tasks 4, 6 and 7 read: `low, mid, high, sell_at, p_touch, p_stop_first, p_up, breakeven, p_breakeven, version, basis, drift, horizon, cost_price, recheck_by, status`.
    - With `forecast` and `horizon` and `bench_closes`: basis `"forecast"`, moves from `paired_moves` (the last `LOOKBACK` common closes up to `day`), `drift = median_drift(the last LOOKBACK benchmark closes dated on or before day, horizon)` (R6: the benchmark check gets the same drift window through this function).
    - Otherwise: basis `"volatility"`, `horizon = NO_FORECAST_HORIZON`, the asset's own log returns over its last `LOOKBACK` closes up to `day` (at most 251 returns).
    - `recheck_by` = `recheck(plan horizon).isoformat()`, from the plan's own horizon (R5): a forecast that falls back to volatility rechecks at 21. None when `recheck` is None (the benchmark check).
    - `cost_price = price × cost_cad / value_cad` (the native cost per unit, for "+N% on cost", R8) when `value_cad > 0`, else None. `breakeven = cost_price` when `value_cad < cost_cad`, else None.
    - `price` None, non-finite or not positive raises `NoPlan("no price")`. Closes dated after `day` are ignored. Any non-finite number in the result raises `NoPlan("plan is not finite")`.
    - The plan stores floats, unrounded; the web formats.

    - Coins (R3, `market == CRYPTO`): the chosen coin model's rows, sampled the same way, each judged with its forecast masked: one `"coin"` plan, horizon 21 panel rows (the coin panel has a row for every day with a BTC close). There is no forecast class for coins.

A pair whose horizon runs past the panel's last row, or whose plan raises `NoPlan`, is skipped.
    - The pair is treated as bought on the sample day. Break-even is tested with a synthetic cost: `cost_cad` = the highest close of the 126 sessions up to and including the sample day, `value_cad` = the price, so `breakeven` = that high (none when the price is at it, so some pairs are under water and some are not).
